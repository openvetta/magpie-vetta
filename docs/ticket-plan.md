# Magpie Agent Vetta 任务拆分草案

日期：2026-11-24。来源：本项目规格草案和已确认需求。
状态：待用户确认拆分；尚未发布任务，也未开始实现。

## 拆分原则

每票交付能独立演示或验证的用户行为，并包含该行为所需的宿主适配、配置对接和测试。当前项目没有实现代码，无需单列重构或基础设施层任务。测试环境和最小测试资源随首次需要它们的切片建立。

沿用规格的主要测试边界：插件安装 → Agent 识别 → Library 分配 → Vetta 实际使用 → 撤回；该测试边界此前仍待确认，本次不将用户请求拆票视为已经确认该边界。

票号为草案稳定标识。Blocked by 只列直接阻塞，不重复列传递依赖。所有票均保持独立插件、不改模型配置、不修改或重新编译上游的约束。

## 01：默认目录下识别 Vetta 并使用一个 stdio MCP

**What to build:** 在 Windows 默认目录的最小环境中，用户独立安装插件后，Magpie 识别 Vetta，用户在 Library 分配一个 stdio MCP，Vetta 新会话实际调用工具，并能在撤回后观察分配消失。完成最短可用闭环。

**Blocked by:** None (can start immediately)。

**Draft acceptance criteria:**

- [ ] 无需修改或重新编译上游即可安装；Agents 和 Library 能识别真实且已校验的 Vetta 目标。
- [ ] 宿主必需的连接契约得到可用适配；可见开关不因空连接返回而报错，不接管 Vetta 模型配置。
- [ ] 从 Library 分配测试 stdio MCP 后，真实 Windows Vetta Desktop 新会话调用可控工具并取得预期结果。
- [ ] 取消测试资源分配后，新会话不再由该分配获得工具；隔离其他来源以排除假阳性。
- [ ] 未发现可信 Vetta 时不创建错误用户资源；后续票再补全自定义目录和交互兜底。
- [ ] 使用隔离用户目录验证安装、重复启用、分配及撤回；已有模型配置和无关资源保持不变。
- [ ] 若无法在独立插件约束内满足注册和分发，交付可复现的接口限制并重新决策，不默认改上游或删减需求。

**Spec coverage:** A1、A2、A5（stdio）、A10、A11、A13、A14（发现/注册失败）。

## 02：直接分配并使用带附属资源的 Skill

**What to build:** 用户从 Library 向 Vetta 直接分配一个 Skill，Vetta 发现描述、加载正文、读取相对资源并执行获准的最小脚本，撤回后新会话不再由该分配获得此 Skill。

**Blocked by:** 01：默认目录下识别 Vetta 并使用一个 stdio MCP。

**Draft acceptance criteria:**

- [ ] 使用已建立的 Agent 和目标适配，从 Library 直接分配 Skill，无需另外复制或维护能力包。
- [ ] Vetta 可发现 Skill 名称描述、加载完整正文、读取相对资源，并在既有权限允许下执行最小脚本。
- [ ] 宿主采用链接或副本时，Windows 上的实际读取均符合所承诺的支持方式；未验证的方式不声明已支持。
- [ ] 撤回后，新会话不再从该分配发现测试 Skill，不误删除无关自有资源。
- [ ] 资源写入使用 Vetta 专属入口，不将其他 Agent 的共享资源入口作为默认目标。
- [ ] 权限拒绝可定位，不绕过 Vetta 的执行审批；自动化契约测试与 Desktop 烟雾验收都有实际加载证据。

**Spec coverage:** A7、A10、A11、A14（权限拒绝）。

## 03：通过 HTTP 直连与 MCP router 使用工具

**What to build:** 用户按 Library 选择，以 HTTP 直接分发或 Magpie MCP router 使用 MCP；传输、鉴权、工具调用和撤回均能实际工作。

**Blocked by:** 01：默认目录下识别 Vetta 并使用一个 stdio MCP。

**Draft acceptance criteria:**

- [ ] HTTP MCP 的显式传输类型、地址及鉴权请求头在 Vetta 中生效，测试 server 实际收到预期鉴权和参数。
- [ ] router 启用时，新会话可发现并调用获分配工具，不列出或执行隔离环境中未获分配的测试工具。
- [ ] router 关闭或单项设为直接分发时，对应 HTTP/stdio 工具按宿主选择工作；不改变用户全局设置来规避兼容问题。
- [ ] 直连和 router 资源均可由 Library 撤回，并在新会话观察正确结果。
- [ ] server 不可用、鉴权失败可观察，不显示伪成功；诊断不输出凭据。
- [ ] 明确 SSE 在验证版本中的兼容结果及限制，不将 HTTP 测试通过当成 SSE 已通过。

**Spec coverage:** A5（HTTP/headers）、A6、A10、A14（连接/鉴权失败）。

## 04：通过 Skill router 按需使用能力包

**What to build:** 用户打开 Skill router 后，Vetta 从可见路由入口按需读取 Skill 正文和附属资源；用户关闭 router 或选择直接分发时仍能正常使用。

**Blocked by:** 02：直接分配并使用带附属资源的 Skill。

**Draft acceptance criteria:**

- [ ] 路由入口在 Vetta 可发现，目标 Skill 可按正文中给出的路径读取，包括 router 内部隐藏路径。
- [ ] 附带资源与获准脚本仍可定位和使用，不通过递归展开全部内部 Skills 来绕过 router。
- [ ] 核查初始 Skill 描述集合，router 内部 Skills 不因适配被逐项重复注入。
- [ ] router 关闭、单项直接分发、重新打开时，都按 Library 选择加载，无重复入口残留。
- [ ] 撤回路由中的一个测试 Skill 后，新会话无法通过该分配再获得它，其余分配保持可用。
- [ ] 在受支持的 Windows 版本组合中执行真实资源加载验收，而不是只断言入口文档生成成功。

**Spec coverage:** A8、A10、A13。

## 05：自动发现可信的自定义 Vetta 目录并使用 MCP

**What to build:** 使用自定义数据根或 Agent 根的用户，无需手填目录即可在存在唯一可信候选时完成 Agent 识别、MCP 分配、实际调用与撤回。

**Blocked by:** 01：默认目录下识别 Vetta 并使用一个 stdio MCP。

**Draft acceptance criteria:**

- [ ] 自动检查可用环境配置、默认位置及能可靠获得的运行/启动关联信息；将自定义数据根与自定义 Agent 根分别验证。
- [ ] 唯一可信候选自动采用，测试 MCP 到达 Vetta runtime 实际读取位置并能真实调用。
- [ ] 安装目录、数据根、Agent 根和项目目录有明确区分，不把安装路径直接当资源目录。
- [ ] Magpie 和 Vetta 环境不一致或存在旧目录时，证据不足即停止写入并报告未确认状态；下一票补全选择体验。
- [ ] 撤回操作对实际目标生效，旧目录与无关目录不因扫描而被改写。
- [ ] 自动发现过程不泄露环境中的密钥；不得仅凭搜索先后顺序或单个同名文件认定目标。

**Spec coverage:** A3、A4（拒绝误选）、A10、A14（目标未确认）。

## 06：多个候选或发现失败时选择并校验目标

**What to build:** 无法自动确定目录时，用户能看到可理解的发现结果，选择或指定目标，校验通过后通过原有 Library 流程实际使用资源。

**Blocked by:** 05：自动发现可信的自定义 Vetta 目录并使用 MCP。

**Draft acceptance criteria:**

- [ ] 多个有效候选、只有旧目录、无候选分别给出准确状态，不显示虚假接通或先写入后询问。
- [ ] 用户可选择候选或指定位置；校验未通过或取消选择时不写入资源。
- [ ] 目标确认后，Library 分配的测试 MCP 可在对应 Vetta 新会话真实调用并撤回。
- [ ] 重复刷新或重新启动插件后，不悄悄将已确认目标换为另一候选；目标失效时重新进入未确认状态。
- [ ] 保留或切换已选目标时，不将旧目标上的宿主管理资源留作无说明的成功状态；遵循原生撤回边界并验证结果。
- [ ] 兜底只服务于目录发现，不新增一套资源分配或冲突管理界面。

**Spec coverage:** A4（完整兜底）、A10、A13、A14。

## 07：原生接管语义、重复操作和撤回卸载流程

**What to build:** 已有资源的用户可以按 Magpie 原生选择完成接管、冲突处理和撤回，并按明确顺序卸载插件；行为与宿主一致，无插件额外覆盖政策。

**Blocked by:** 02：直接分配并使用带附属资源的 Skill（通过 02 已依赖 01，不重复列传递依赖）。

**Draft acceptance criteria:**

- [ ] 同名 MCP 核心字段接管、其他字段保留与取消分发结果符合宿主行为，不宣称能自动恢复未验证的原有项。
- [ ] 同名不同内容 Skill 使用宿主原生取舍；保留自有版本与采用 Library 版本的结果均能在 Vetta 观察。
- [ ] 项目配置覆盖/合并和其他资源来源被隔离记录，不将其他来源仍存在误判为该分配撤回失败。
- [ ] 重复启用、分配、撤回及刷新不累积重复 Agent、重复入口或插件自行制造的遗留资源。
- [ ] 先在 Library 撤回资源，再关闭/卸载插件，实际配置与新会话结果有证据；保留和遗留项按宿主语义解释。
- [ ] 直接关闭/卸载的已知限制说明准确，不承诺未经验证的自动清理。
- [ ] 贯穿验证模型配置、无关自有资源和其他 Agent 的分配不被插件改写。

**Spec coverage:** A9、A10、A11、A12、A13。

## 08：独立安装包的 Windows Desktop 全流程验收

**What to build:** 用户拿到独立安装包后，能够依照说明在明确的 Windows 版本组合中完成自动发现、资源分配、真实使用和撤回卸载；支持范围和限制有实测依据。

**Blocked by:** 03：通过 HTTP 直连与 MCP router 使用工具；04：通过 Skill router 按需使用能力包；06：多个候选或发现失败时选择并校验目标；07：原生接管语义、重复操作和撤回卸载流程。

**Draft acceptance criteria:**

- [ ] 从可分发的独立包安装，不依赖源码 checkout 或重新编译上游，验证包中包含全部运行所需资源。
- [ ] 在实际 Windows Desktop 上覆盖默认与自定义目录、选择兜底、MCP 直连/router、Skills 直连/router 组合。
- [ ] 自定义目录下也完成 Skill 发现、正文/附属资源读取、router 和撤回验证，补齐前序分支交叉组合。
- [ ] 新会话可靠读取最新分配；记录后续轮次刷新能力和在途快照行为，不把即时热更新列作虚假承诺。
- [ ] 记录实际验证的 Magpie、Vetta 发行版本；静态调研 commit 不冒充最低兼容发行版。
- [ ] 提供安装、目录发现、原生管理选择、失败诊断、先撤回再卸载的使用说明，不输出凭据或工具正文。
- [ ] 汇总规格 A1–A14 的验收证据；没有遗漏首版场景，也没有将 CLI/macOS/Linux 或后续统计列为已支持。
- [ ] 最终仍有接口限制或测试失败时明确报告，不以修改上游、接管模型或关闭 router 的方式假通过。

**Spec coverage:** A1–A14 的独立包与真实 Desktop 回归；重点补齐跨分支组合。

## 09：公开发布并在 Magpie 插件界面搜索安装

**What to build:** 用户无需下载源码或指定本地文件夹，即可在受支持 Magpie 的插件发现/搜索界面找到 Vetta Agent 插件，并从界面下载安装后实际使用。

**Blocked by:** 08：独立安装包的 Windows Desktop 全流程验收。

**Draft acceptance criteria:**

- [ ] 公开发布可安装的受验收版本，包声明能被 Magpie 识别为 Agent，名称、说明、许可和来源一致。
- [ ] GitHub 仓库采用 Magpie 支持的社区发现标记；满足实际发行版本的发现筛选条件，不依赖用户手填仓库地址来冒充“可搜索”。
- [ ] 在真实 Magpie 插件发现/搜索界面找到条目；考虑 GitHub 索引及 Magpie 缓存刷新，不承诺发布后即时可见。
- [ ] 从界面下载安装成功，实际安装来源和版本可确认，完成 Vetta 识别及 MCP/Skills 使用烟雾验收。
- [ ] 若使用 npm，验证公开包确实可用且归属正确；若使用 GitHub，验证该来源能独立安装，不依赖发布者本地文件。
- [ ] 如另行申请官方社区目录收录，记录 PR 与结果；未合并前不宣称官方目录已收录，且不将它替代社区发现路径的实测。
- [ ] 发布过程不修改上游应用源码，不发布尚未通过首版验收的功能承诺。

**Spec coverage:** A15，并从公开安装来源复验核心闭环。

## 依赖与可并行前沿

- 初始仅 01 可开始，它建立最短真实闭环并验证独立插件契约。
- 01 完成后，02、03、05 可并行推进。
- 02 完成后，04 与 07 可开始；不因自动发现分支尚未完成而阻塞默认目录的 Skills 工作。
- 05 完成后，06 可开始。
- 03、04、06、07 完成后，08 汇总完整版本组合与独立包回归。
- 08 完成后，09 验证公开发现与下载安装，完成用户补充的市场交付要求。

07 不依赖 router 或路径异常分支，因为其目标是默认场景中的原生接管和生命周期语义；08 才负责这些能力与各分支的交叉回归。依赖只表达实施前置条件，不表示“无阻塞的票已经实现”。
