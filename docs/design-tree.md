## 已确认的阶段决策

### D1 会话统计和调用记录的交付阶段

背景：用户曾明确包含会话统计和工具调用，最新澄清强调资源接入是主要目标。MCP 工具“能够执行”和工具“能够统计”须区分。

决策：首版聚焦 Agent 识别、MCP/Skills 分配和实际使用；会话统计与调用记录保留为后续阶段需求。

状态：已确认。用户于 2026-11-24 回复“同意”。MCP 工具实际执行仍是首版必需能力。

### D2 首版验收产品与平台

决策：以 Windows 的 Vetta Desktop 为首版必测目标，兼容能力尽量复用跨平台路径规则；CLI、macOS 和 Linux 的正式支持承诺待各自验证后再增加。

状态：已确认。用户于 2026-11-24 对该建议回复“同意”。最低版本仍待核查。

## 已确认的资源管理决策

### D3 资源管理沿用 Magpie 原生机制

用户指出：Magpie 已提供是否统一管理的选择。原先单独要求选择“用户原有项优先”的问题撤回，因为它引入了不同于 Magpie 宿主的额外冲突策略。

修正方向：插件声明 Vetta 身份和资源入口；用户在 Magpie Library 中选择分配与接管，具体冲突和撤回沿用宿主机制。将实际行为作为验收与使用说明的依据，不把宿主未提供的保护写成插件承诺。

状态：已确认。用户于 2026-11-24 回复“确认”，接受复用 Magpie 原生资源管理机制。

源码确认 MCP 和 Skills 的规则不同：claude 格式同名 MCP 会合并并接管核心字段，取消分发可能移除整个已应用条目；Skills 同名不同内容保留原目录并提供取舍。详见 requirements.md。统一管理不是“所有同名项一律跳过”。

当前没有要求用户再次选择同名覆盖策略。若验收暴露宿主机制无法满足核心目标，再讨论必要的补充能力。

## 已确认的刷新边界

### D4 资源变更的生效边界

决策：首版以新会话能够使用最新资源为保底验收；尽量利用 Vetta 已有刷新能力，让后续轮次读取变化。正在进行的轮次允许持有原快照，不要求中途替换工具和技能。MCP 的后续轮次刷新链尚未完整验证，不提前承诺写入即刻生效。

状态：已确认。用户于 2026-11-24 回复“同意”。

## 已确认的交付边界

### D5 独立插件的交付边界

决策：首版应作为可独立安装的 Magpie 插件交付，面向无需修改或重新编译的 Magpie 和 Vetta。宿主要求的 config/connect 通过插件自身适配解决，不接管 Vetta 模型配置。若现有 API 的限制导致必须修改任一上游源码，先说明限制和方案，再重新决策。

状态：已确认。用户于 2026-11-24 回复“同意”。独立状态配置是候选工程实现，不等于已验证完成。

## 已确认的目录发现要求

### D6 首版自定义数据目录支持

用户追问“就不能自动扫吗”，指出应先探索自动发现而不是直接排除自定义目录。撤回“首版仅支持默认目录”的建议，该建议未获用户同意。

修正方案：将自动发现作为首选体验，检查可用的环境配置、默认位置及能可靠获取的运行/启动信息，校验候选数据根和 Agent 根。自定义目录列入设计与验收；运行实例信息的可获取程度需验证，不承诺任意位置必然可自动发现。

状态：已确认。用户于 2026-11-24 回复“确认”，接受自动发现优先、唯一可信候选自动使用，以及找不到或多个有效候选时选择/指定路径的兜底方案。具体发现手段仍需技术验证。

技术边界：安装位置不等于数据目录；Magpie 可见环境不等于 Vetta 进程环境；磁盘中遗留的旧目录不等于正在使用的目录。扫描必须先校验候选和关联证据，不按首次命中直接写入。优先受限、有依据的查找，整盘扫描是否有必要由后续工程验证决定。

## 需要查证的技术前提

以下是工程查证任务，不向用户索要能从源码获得的事实：

- F1（静态查证完成）：宿主要求 config 及 model/connect，Library target 不依赖模型已连接；纯 Library-only 声明不被原生支持，需设计可用的连接状态适配。
- F2（静态查证完成）：数据根受 VETTA_HOME、VETTA_CONFIG_DIR 控制，Agent 根另受 VETTA_CODING_AGENT_DIR 控制；Desktop UI 与 runtime 在自定义 agentDir 时可能分歧。
- F3（形状匹配，集成待验证）：Magpie claude HTTP 的 type/http、url、headers 与 Vetta schema/transport 对应；SSE 的 protocolMode 限制须单独验收。
- F4（静态查证完成，刷新链和清理实测待补）：Skills 按轮次捕获快照，MCP 有重载机制；移除插件不等于撤回 Library 分发。
- F5（部分确认）：普通链接可发现；隐藏 .skills 不递归发现是 router 降低提示开销的预期结构，不能据此判断 router 不兼容，仍需验证按正文路径加载。
- F6（后续阶段）：现有 Vetta 请求能否被 Magpie 识别为 Vetta，以及是否已有稳定会话标识传递。

## 产品决策与工程验证的分界

- 最低版本：属于后续兼容性验证结果，尚不声明版本号；不让用户猜测哪个版本满足接口契约。
- 接入方式：D5 已确定独立插件边界，描述文件和插件自身运行时由工程验证决定；上游修改不在当前授权范围。
- 刷新体验：D4 已确定新会话读取最新资源为保底，后续验证轮次刷新，不再作为未决需求。
- 冲突与撤回：D3 已确定复用 Magpie 原生语义；卸载清理的限制写入使用说明并在集成中验证，不另造覆盖策略。
- 统计范围：后续阶段结合 F6 讨论会话用量、MCP 调用记录和 Vetta 本地工具记录各自的覆盖范围。

当前首版产品决策前沿已收敛：D1–D6 均已逐项确认。剩余注册适配、路径发现实现、最低版本和集成结果是工程验证事项；只有验证导致产品范围或交付边界需要变化时再发起新的决策。
